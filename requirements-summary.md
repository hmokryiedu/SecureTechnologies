# Лабораторная работа №1 - Требования (Подробная сводка)

## Цель работы
Изучить рекомендации по формированию паролей и их взлом с помощью атак подбором, по словарю и с применением правил.

---

## Общее описание задания

Разработать программное обеспечение для **имитации процесса взлома пароля** с применением атаки перебором.

### Участники проекта (2 студента):
1. **Администратор** - разрабатывает серверное приложение, задает логины и пароли
2. **Хакер** - разрабатывает клиентское приложение, пытается раскрыть пароли

### Технология взаимодействия
- **Именованные каналы (Named Pipes)** с возможностью работы по локальной сети
- Приложения могут быть консольными или с GUI

---

## Серверное приложение (Администратор)

### Основной алгоритм работы:

1. **Запуск**: запросить имя текстового файла с логинами/паролями через `GetOpenFileName`
   - Формат файла:
     - 1-я строка: `макс_длина_логина макс_длина_пароля` (через пробел)
     - Далее по строкам: `логин пароль` (5 пар)

2. **Считать содержимое файла**

3. **Выбор режима работы** (для 100%+):
   - Обычный режим
   - С противодействием взлому

4. **Создание именованного канала**:
   - **Минимум 3 экземпляра** канала
   - **Асинхронный режим** работы
   - Имя канала должно совпадать на сервере и клиенте

5. **Ожидание подключения клиентов**

6. **При подключении клиента**:
   - Считать логин и пароль (строки)
   - Если совпадают с заданными → отправить клиенту `1`
   - Иначе → отправить `0`
   - Отключить клиента

7. **Переход к пункту 5**

8. **Если все клиенты отключены**: запросить продолжение через `MessageBox`

9. **Если пользователь выбрал продолжение** → переход к пункту 5

### Дополнительные требования к серверу:
- Обеспечить возможность **подключения по сети**
- **Режим защиты от взлома** (увеличение времени ответа):
  - Реализовать через **пропуск обработки запросов** от логина в течение указанного времени (мс)
  - Задержки для каждого логина **НЕ должны влиять** на скорость работы сервера в целом

## Клиентское приложение (Хакер)

### Основной алгоритм работы:

1. **Ввод параметров пользователем**:

   **Выбор типа работы:**
   - **Проверка связи**: ввод тестовых логина и пароля
   - **Взлом**: выбор режима (для 100%+)

   **Для режима полного перебора:**
   - Тип алфавита пароля:
     - **27 символов**: маленькие латинские буквы + апостроф
     - **63 символа**: маленькие + большие латинские буквы + апостроф + цифры
     - **128 символов**: латиница + апостроф + цифры + кириллица (маленькие + большие)
   - Максимально допустимая длина пароля
   - Логин для взлома

   **Для режима атаки на основе правил (100%+):**
   - Реализовать **правила в виде методов класса**, применяемые к списку вероятных паролей:
     - a) Замена букв на латиницу/кириллицу (смена раскладки)
     - b) Изменение регистра
     - c) Изменение порядка следования букв
     - и т.д.
   - Ввод имени файла через `GetOpenFileName`:
     - Скриптовый файл с наиболее вероятными паролями и типами правил
     - Для каждого типа правила указан список паролей (в отдельном файле)
   - **Хранение данных**: однонаправленные линейные списки (шаблонный класс)

2. **Подключение к именованному каналу**:
   - Если канал не создан → сообщение об ошибке, завершение
   - Если сервер занят → ожидание освобождения, затем подключение

3. **Обмен данными с сервером**:
   - Отправить логин и пароль
   - Получить подтверждение авторизации
   - **В режиме взлома**: повторять пункт 3 (или 2-3) до положительного ответа
   - **ВАЖНО: НЕ использовать рекурсию при взломе**

4. **Вывод результата**:
   - **Режим взлома**: логин, найденный пароль, макс. длина, алфавит, **время поиска**
   - **Проверка связи**: сообщение об удачности/неудачности

5. **Отключение от канала и завершение работы**

## Требования к паролям (4 неизвестных пароля)

Пароли задаются для:
- **3 типов алфавитов** (27, 63, 128 символов)
- **3 различных максимальных длин** (не менее 3 символов)

**Итого: 4 × 3 × 3 = 36 неизвестных паролей**

### Характеристики паролей:
| № пароля | Нарушает рекомендацию |
|----------|----------------------|
| 1 | 1-ую (общеизвестные пароли: 111, 123, qwerty) |
| 2 | 2-ую (личные данные: дата рождения, имена) |
| 3 | 5-ую (слишком короткий пароль) |
| 4 | Не нарушает никаких рекомендаций |

**ВАЖНО:**
- Хакеру неизвестно, какой пароль какую рекомендацию нарушает
- ВСЕ пароли должны удовлетворять рекомендации №7 (пригодность для запоминания)

## Рекомендации по формированию паролей (из теории)

1. НЕ задавать общеизвестные пароли (111, 123, qwerty)
2. НЕ использовать личные данные (дата рождения, имена родственников, клички питомцев)
3. НЕ использовать словарные слова
4. НЕ использовать шаблоны (логин + номер)
5. НЕ использовать слишком короткие пароли
6. НЕ использовать всегда одинаковую длину
7. Пароль должен быть пригоден для запоминания

## Уровни сложности и оценивание

### 75% баллов:
- Клиент: поиск пароля **полным перебором**
- Сервер: **без** специальных действий против взлома

### 100% баллов:
- Клиент: полный перебор + **атака на основе правил** со списком вероятных паролей
- Сервер: **2 режима работы** (с противодействием и без)

### 140% баллов*:
- Всё из 100% + **многопоточность** клиента и сервера

### Бонусы ±15%:
- При взломе ≥60% паролей (≥22 из 36): **Хакер +15%**
- При взломе <60%: **Администратор +15%**
- При 2 режимах работы количество паролей ×4

## WinAPI функции для Named Pipes (ключевые)

### Серверная сторона:

| Функция | Назначение |
|---------|------------|
| `CreateNamedPipe` | Создание экземпляра канала |
| `ConnectNamedPipe` | Ожидание подключения клиента |
| `DisconnectNamedPipe` | Отсоединение клиента |
| `CloseHandle` | Освобождение ресурсов |

### Клиентская сторона:

| Функция | Назначение |
|---------|------------|
| `CreateFile` | Получение дескриптора канала |
| `WaitNamedPipe` | Ожидание доступности канала |
| `SetNamedPipeHandleState` | Изменение режима работы канала |
| `CloseHandle` | Освобождение ресурсов |

### Формат имени канала:
```
\\.\pipe\имя_канала
```
- Максимум 256 символов
- Нельзя использовать `\` в имени
- В C++ символ `\` нужно дублировать: `\\\\.\\pipe\\...`

### Важные константы режимов:

**Режимы доступа (dwOpenMode):**
- `PIPE_ACCESS_DUPLEX` (0x00000003) - двунаправленный
- `PIPE_ACCESS_INBOUND` (0x00000001) - клиент пишет, сервер читает
- `PIPE_ACCESS_OUTBOUND` (0x00000002) - сервер пишет, клиент читает

**Дополнительные флаги:**
- `FILE_FLAG_OVERLAPPED` (0x40000000) - **асинхронный режим** (ОБЯЗАТЕЛЬНО для сервера!)

**Режимы работы (dwPipeMode):**
- `PIPE_TYPE_BYTE` / `PIPE_TYPE_MESSAGE` - режим записи
- `PIPE_READMODE_BYTE` / `PIPE_READMODE_MESSAGE` - режим чтения
- `PIPE_WAIT` / `PIPE_NOWAIT` - блокировка

### Важные замечания по асинхронному режиму:
- Структура `OVERLAPPED` должна содержать **дескриптор события с РУЧНЫМ сбросом**
- Перед чтением/записью обнулить поля: `Offset`, `OffsetHigh`, `Internal`, `InternalHigh`
- После операций **НЕ НУЖНО** вручную изменять `Offset` и `OffsetHigh`
- Система автоматически изменяет `Internal` и `InternalHigh`
- Состояние событий меняется **АВТОМАТИЧЕСКИ**

## Сетевые особенности

- Если клиент и сервер на **одном компьютере**, но указано имя отличное от `.`:
  - При отключенной сети → ошибка 1231 (сеть недоступна)
  - При установленном протоколе NWLink IPX/SPX/NetBIOS → ошибка 53 (неправильный сетевой путь)

## Типы атак (теория)

1. **Полный перебор (brute force)** - перебор всех возможных комбинаций
2. **Атака по словарю** - подстановка слов из словаря
3. **Атака по слогам** - подбор из слогов языка
4. **Атака на основе правил** - комбинация перебора с эвристиками

### Формула расчета вариантов:
- При алфавите 62 символа и длине n=10: N = 62^10 ≈ 8.4 × 10^17
- При алфавите 128 символов и длине n=10: N = 128^10 ≈ 1.18 × 10^21

## Методы противодействия взлому

1. **Увеличение времени ответа** при превышении неудачных попыток
2. **Блокировка логина** при большом количестве неудачных попыток
